# SGLang 实测结果（2026-08-15）

环境：单张 NVIDIA L20（46,068 MiB）、SGLang 0.5.16、
Qwen3.8-27B-FP8、TP=1、32K、FP8 KV、MTP Off、完整多模态。默认
8192-token prefill CUDA Graph 在启动时 OOM，因此只禁用 prefill graph，保留
decode CUDA Graph。服务按当前可用 KV 容量实际同时运行 6 个请求。

本目录保留两组口径：不带 `-r1` 的 JSON 是最初 day0 基线；带 `-r1` 的 JSON
是后续统一复测，由同一个 vLLM Pod 作为客户端，通过 Kubernetes Service 访问
两个后端。后续横向参考应以 `-r1` 结果为准。

统一复测均使用同一 Tokenizer 和 seed，`request-rate=inf`、
`temperature=0`、`ignore-eos=true`。表中 TTFT、TPOT 和 E2EL 均为毫秒。

## 短请求并发边界：128 输入 / 64 输出

| 客户端并发 | 成功 | req/s | 输出 tok/s | p50 / p95 / p99 TTFT | p95 TPOT | p95 E2EL |
| ---: | ---: | ---: | ---: | --- | ---: | ---: |
| 4 | 256/256 | 1.25 | 80.10 | 214.90 / 216.43 / 219.08 | 47.35 | 3,198.55 |
| 6 | 256/256 | 1.78 | 114.17 | 290.98 / 293.51 / 318.26 | 48.40 | 3,342.24 |
| 8 | 256/256 | 1.78 | 114.22 | 290.90 / 3,632.09 / 3,633.37 | 48.43 | 6,682.14 |
| 10 | 256/256 | 1.78 | 114.19 | 3,629.45 / 3,634.25 / 3,637.80 | 48.44 | 6,685.32 |

C6 以后输出吞吐没有继续增长。现场指标在 C8 为 6 个运行、2 个等待，在 C10
为 6 个运行、4 个等待，因此吞吐平台和 TTFT 跃升都能由内部并发上限解释。
C10 的 p95 指标由详细时间数组补算。

## 4K 共享前缀：4096 前缀 / 256 后缀 / 128 输出

5 组共享前缀、20 个请求、并发 4；第二轮立即复用完全相同的数据。

| 轮次 | 成功 | 整轮耗时（s） | 输出 tok/s | p50 / p95 TTFT | p95 E2EL |
| --- | ---: | ---: | ---: | --- | ---: |
| 首轮 | 20/20 | 49.51 | 51.70 | 4,324.93 / 5,487.65 | 11,573.21 |
| 热缓存复跑 | 20/20 | 34.02 | 75.26 | 431.32 / 1,674.02 | 7,799.02 |

热缓存复跑的延迟变化很明显，但本次采样时 `sglang:cache_hit_rate` 仍报告 0；
这项监控口径需要单独复核，不能直接把瞬时指标当作此次请求的实际命中率。

| 8,192 | 4 | 4/4 | 2,738.75 / 2,744.12 | 51.07 | 15,763.76 |

30,720 输入加 256 输出在当前 32K 配置下 4/4 成功，没有长度拒绝、OOM 或
Pod 重启。仓库 JSON 已移除生成文本、逐请求 token 数组和内部时间线，只保留
发布所需的汇总指标。
